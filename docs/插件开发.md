# 插件开发

WorkerBBS 内置一套轻量插件系统，让你**在不改主程序核心代码的前提下**，给论坛扩展新功能、对接论坛 REST API。

本仓库已附带一个示例插件「每日签到」，下文以它为模板讲解。

---

## 1. 插件模型

- **代码内置、随仓库部署**：插件是 TypeScript 文件，放在 `src/plugins/builtin/`，随主仓库一起 `wrangler deploy`。
  这样做比「运行时上传 zip」更安全——插件代码经过类型检查和打包，不会在运行时执行不可信脚本。
- **后台开关 + 配置**：每个插件在数据库里有 `enabled` 开关和 `config`（JSON）。在 `/admin → 插件` 面板里启用 / 禁用。
- **能力**：插件可以
  1. 通过 `ctx.app` 挂载自己的 **REST 接口**（统一前缀 `/api/plugins/xxx`）；
  2. 通过 `ctx.on(...)` **订阅论坛生命周期钩子**（发帖、回复、注册、关注、点赞）；
  3. 通过 `ctx` 读写**配置 / KV / 给用户加经验 / 调用论坛 API**。

> 前端配套：插件也可提供前端页面（见第 5 节），自动出现在左侧导航。

## 2. 目录结构

```
src/plugins/
├── types.ts                # ForumPlugin / PluginContext / ForumHookEvent 类型定义
├── index.ts                # 插件框架核心（注册、钩子触发、启用态缓存）
└── builtin/
    └── checkin.ts          # 示例插件：每日签到

public/
├── plugin-host.js          # 前端宿主：window.WB.registerPlugin()
└── plugins/
    └── checkin.js          # 示例插件前端页面
```

## 3. 后端插件 API

### 3.1 插件定义

```ts
import type { ForumPlugin } from '../types';

export const myPlugin: ForumPlugin = {
  id: 'myplugin',          // 唯一英文 ID（数据库开关、前端路由都用它）
  name: '我的插件',
  description: '一句话简介',
  version: '1.0.0',
  setup(ctx) {
    // 在这里挂载路由、订阅钩子
  },
};
```

然后在 `src/plugins/index.ts` 的 `registry` 数组里登记：

```ts
import { myPlugin } from './builtin/myplugin';
const registry: ForumPlugin[] = [checkinPlugin, myPlugin];
```

### 3.2 PluginContext（setup 时注入）

| 方法 | 说明 |
|---|---|
| `ctx.app` | Hono 实例，用 `ctx.app.get('/api/plugins/xxx', ...)` 挂载路由 |
| `ctx.on(event, handler)` | 订阅生命周期钩子（见 3.3） |
| `ctx.isEnabled()` | 该插件当前是否启用（后台开关） |
| `ctx.getConfig(key, fallback?)` / `ctx.setConfig(key, value)` | 读写插件配置（持久化 JSON） |
| `ctx.kvGet(key, fallback?)` / `ctx.kvSet(key, value)` | 轻量 KV 存储（plugin 命名空间隔离，适合计数器、状态位） |
| `ctx.addExp(userId, amount)` | 给用户加经验值（复用主站逻辑） |
| `ctx.json(data, status?)` | 构造统一的 JSON 响应 |

### 3.3 生命周期钩子

在 `setup` 里用 `ctx.on(event, (c, data) => {...})` 订阅。只有**已启用**的插件才会收到钩子。

| 事件 | `data` 内容 | 触发时机 |
|---|---|---|
| `thread:created` | `{ threadId, title, boardId, author, userId }` | 新帖发布 |
| `reply:created` | `{ threadId, author, userId }` | 新回复 |
| `user:registered` | `{ userId, username, email }` | 新用户注册（无论是否开启邮箱验证） |
| `user:followed` | `{ followerId, targetId, is_following }` | 关注 / 取消关注切换 |
| `thread:liked` | `{ threadId, liked, byUserId, userId }` | 帖子点赞 / 取消 |

`c` 是 Hono 的 Context，可通过 `c.get('user')` 拿到当前登录用户、`c.env` 拿到 Bindings。

### 3.4 路由鉴权约定

插件路由复用主站中间件，能拿到 `c.get('user')`。建议：

```ts
ctx.app.get('/api/plugins/xxx', async (c) => {
  const u = c.get('user');
  if (!u) return ctx.json({ error: '请先登录' }, 401);
  if (!(await ctx.isEnabled())) return ctx.json({ error: '插件未启用' }, 403);
  // ...
});
```

### 3.5 论坛 REST API 速查（插件可直接 fetch / 或调用 db 助手）

| 接口 | 说明 |
|---|---|
| `GET /api/settings` | 站点设置 |
| `GET /api/me` | 当前用户 |
| `GET /api/threads?board=&q=&page=` | 帖子列表 |
| `GET /api/threads/:id` | 帖子详情（含回复） |
| `GET /api/users/:username` | 用户主页 |
| `POST /api/threads` | 发帖 |
| `POST /api/threads/:id/replies` | 回复 |
| `POST /api/threads/:id/like` | 点赞 |
| `POST /api/users/:username/follow` | 关注 |

插件内部若需调用这些接口，可用 `fetch(new URL('/api/threads', c.req.url), {...})`，
并带上 `c.req.header('Cookie')` 以复用当前会话。多数场景直接用 `db` 助手更方便（见 `src/db.ts`）。

## 4. 示例插件：每日签到

完整代码见 `src/plugins/builtin/checkin.ts`，要点如下：

```ts
import type { ForumPlugin } from '../types';

export const checkinPlugin: ForumPlugin = {
  id: 'checkin',
  name: '每日签到',
  description: '用户每日签到获得经验值，记录连续签到天数，防止重复签到。',
  version: '1.0.0',
  setup(ctx) {
    const today = () => new Date().toISOString().slice(0, 10);

    ctx.app.get('/api/plugins/checkin', async (c) => {
      const u = c.get('user');
      if (!u) return ctx.json({ error: '请先登录' }, 401);
      if (!(await ctx.isEnabled())) return ctx.json({ error: '插件未启用' }, 403);
      const last = await ctx.kvGet('last_' + u.id, '');
      const streak = Number(await ctx.kvGet('streak_' + u.id, '0')) || 0;
      return ctx.json({ checkedIn: last === today(), lastDate: last, streak });
    });

    ctx.app.post('/api/plugins/checkin', async (c) => {
      const u = c.get('user');
      if (!u) return ctx.json({ error: '请先登录' }, 401);
      if (!(await ctx.isEnabled())) return ctx.json({ error: '插件未启用' }, 403);
      const t = today();
      const last = await ctx.kvGet('last_' + u.id, '');
      if (last === t) return ctx.json({ error: '今天已经签到过了' }, 400);
      const yest = new Date(Date.now() - 86400000).toISOString().slice(0, 10);
      const streak = last === yest ? (Number(await ctx.kvGet('streak_' + u.id, '0')) || 0) + 1 : 1;
      await ctx.kvSet('last_' + u.id, t);
      await ctx.kvSet('streak_' + u.id, String(streak));
      await ctx.addExp(u.id, 5); // 签到奖励经验
      return ctx.json({ ok: true, exp: 5, streak, checkedIn: true });
    });

    // 演示钩子：新用户注册时记录加入日期
    ctx.on('user:registered', async (_c, data) => {
      if (data && data.userId) await ctx.kvSet('joined_' + data.userId, new Date().toISOString());
    });
  },
};
```

## 5. 前端插件页面

前端宿主 `public/plugin-host.js` 提供 `window.WB.registerPlugin()`。在 `public/plugins/checkin.js` 里：

```js
window.WB.registerPlugin({
  id: 'checkin',
  name: '每日签到',
  icon: window.WI ? window.WI('sparkle', 20) : '',
  render(root, ctx) {
    // root 是 #content 里的容器；ctx 提供 api / WI / esc / SETTINGS / ME
    root.innerHTML = '...';
    // 用 ctx.api('/api/plugins/checkin', { method: 'POST' }) 调后端
  },
});
```

**约定**：
- 每个前端插件一个文件，放在 `public/plugins/`，并在 `public/index.html` 里用 `<script>` 引入（**必须放在 `/app.js` 之前**，这样 `buildRail()` 才能生成导航）。
- `render(root, ctx)` 负责把自己渲染进 `root`。`ctx.api` 是与主站一致的 fetch 封装（自动带同域 Cookie）。
- 主应用会自动在左侧导航加一个按钮，路由 `#/plugin/<id>` 下调用该插件的 `render`。

## 6. 注册 / 启用一个插件（操作步骤）

1. 后端：在 `src/plugins/builtin/` 新建文件，导出 `ForumPlugin`，并在 `src/plugins/index.ts` 的 `registry` 登记。
2. 前端（可选）：在 `public/plugins/` 新建 JS，用 `window.WB.registerPlugin` 注册，并在 `index.html` 引入。
3. 重新部署（`wrangler deploy` 或 push 触发 CI）。
4. 数据库迁移：`wrangler d1 migrations apply workerbbs --remote`（首次部署需执行，含 `0006_plugins.sql`）。
5. 进入 `/admin → 插件`，把插件切换为「已启用」。

## 7. 限制与注意

- **插件随仓库部署，不是运行时安装**：便于类型安全与代码审查，但意味着新增插件需要一次部署。
- **钩子只在插件启用时触发**；路由始终挂载，但插件应在内部用 `ctx.isEnabled()` 自行判断是否处理（示例已示范）。
- **启用态有 60 秒缓存**：后台切换后最多 60 秒在全站生效（后台接口会立即刷新缓存，无需等待）。
- **KV 存的是字符串**：数字 / 对象请自行 `JSON.stringify` / 解析。
- **不要在前端插件里放密钥**：前端代码对用户可见，密钥只应留在后端 `settings` / 环境变量。
- 插件代码运行在主 Worker 进程内，请避免无限循环、超大循环或同步阻塞操作。
