# WorkerBBS 部署指南（超级详细）

> 适用版本：含私信（WebSocket 实时定向推送）、插件系统、富文本、主题、邮件验证、WebSocket 中继节点的当前主分支。
> 本文档与**真实代码**保持同步（截至 2026-08-18）。如与 `README.md` 有冲突，**以本文件为准**。

---

## 0. 先看这一节：架构与产物

WorkerBBS 部署后其实是 **两个相互独立的 Cloudflare Worker**：

| Worker | 目录 / 配置 | 作用 | 访问地址示例 |
|--------|-------------|------|--------------|
| **主站** | `src/index.ts` → `wrangler.toml` | 论坛全部 API + 前端 SPA 托管（Hono） | `https://workerbbs.<subdomain>.workers.dev` |
| **WebSocket 中继节点** | `ws/src/index.ts` → `ws/wrangler.toml` | 实时推送（点赞/回复/关注/私信）的广播中继（Durable Object） | `https://workerbbs-ws.<subdomain>.workers.dev` |

关键事实（避免被旧 README 误导）：

- **不使用 R2**。头像、背景图、富文本里的图片/视频都以 **base64 data URL 直接存进 D1**（`users` / `settings` 表），所以你**不需要开通 R2、不需要建 R2 桶、CI 也不会碰 R2**。
- 数据只存在 **一个 D1 数据库** `workerbbs`（主站用；ws 节点只用 Durable Object，不碰 D1）。
- 实时同步走 **WebSocket 中继节点**，现在**不启用广播鉴权（无 API 密钥）**：任何能连上节点的人都可以向 `/broadcast` 推事件。这是设计取舍——部署简单、无需配密钥。若之后要安全再加 `API_KEY`（两端一致）即可（代码已留好位置）。
- 前端是**纯静态 SPA**（无构建步骤），由主站 Worker 通过 `env.ASSETS` 直接托管 `public/` 目录。

## 2. 获取 Cloudflare 凭证

### 2.1 账户 ID（CLOUDFLARE_ACCOUNT_ID）

1. 登录 Cloudflare 控制台 → 右侧点你的账户头像 → **账户主页**。
2. 在「账户 ID」处复制那串 UUID。
3. 这就是后面要填进 GitHub Secrets 的 `CLOUDFLARE_ACCOUNT_ID`。

### 2.2 API Token（CLOUDFLARE_API_TOKEN）

1. 控制台 → 右上角头像 → **我的个人资料** → 左侧 **API 令牌** → **创建令牌**。
2. 推荐：点 **使用模板「编辑 Cloudflare Workers」**（它已包含 Workers 脚本的编辑权限）。
3. **必须额外加的权限**（点「添加更多权限」）：
   - **账户** → **D1** → **编辑**（D1:Edit）—— 建库、跑迁移、注入数据都要它。
   - 如果你要用**自定义域名**（见第 7 节）：
     - **区域（Zone）** → 选你的域名 → **DNS** → **编辑**（DNS:Edit）—— wrangler 部署时会自动给你加 DNS 记录。
   - （可选）**账户** → **Workers KV** → 编辑——本项目没用 KV，可不加。
4. **账户资源** 保持「所有账户」；**区域资源** 若用到自定义域名则选「包含 → 你的域名」，否则「所有区域」。
5. **继续以创建令牌** → 复制生成的 Token。
6. 这就是 `CLOUDFLARE_API_TOKEN`。

> 安全提示：Token 只在 GitHub Secrets 里出现，绝不写进代码或提交。若泄露，立刻在 Cloudflare 控制台「撤销」。

## 4. 配置 GitHub Secrets 与 Variables（一次性）

进入仓库页面 → **Settings → Secrets and variables → Actions**。

### 4.1 Repository secrets（敏感，不可见）

点 **New repository secret**，逐个添加：

| 名称 | 必填 | 说明 |
|------|------|------|
| `CLOUDFLARE_API_TOKEN` | ✅ | 第 2.2 节拿到的 Token。 |
| `CLOUDFLARE_ACCOUNT_ID` | ✅ | 第 2.1 节拿到的账户 UUID。 |
| `ADMIN_EMAIL` | ✅ | 首次部署创建的管理员邮箱，如 `admin@example.com`。 |
| `ADMIN_USERNAME` | 否 | 管理员用户名，默认 `admin`。不填则 CI 用 `admin`。 |
| `ADMIN_PASSWORD` | ✅ | 管理员登录密码（建议强密码）。**只会在首次部署时创建一次**，之后改密码请登录后台改。 |
| `CUSTOM_DOMAIN` | 否 | 自定义访问域名，如 `bbs.example.com`。**不填则只部署到 `*.workers.dev`**，功能不受影响。填了见第 7 节。 |

### 4.2 Repository variables（非敏感，可见）

切到 **Variables** 标签页 → **New repository variable**：

| 名称 | 必填 | 说明 |
|------|------|------|
| `WS_DOMAIN` | 否 | WebSocket 节点的域名，如 `workerbbs-ws.your-subdomain.workers.dev`。**不填则 ws 节点用占位值 `ws.example.workers.dev`（仅展示，不影响连接）**。填了 CI 会把它注入 `ws/wrangler.toml` 的 `NODE_DOMAIN`。 |

> 为什么 ws 地址不填也能用？因为主站真正需要的「WebSocket 端点」是**部署后**从 Cloudflare 拿到的真实地址，要填到后台「实时同步」面板（见第 6.3 节）。`WS_DOMAIN` 只是给节点一个更友好的自报域名，可留空。

## 5. 一键部署（GitHub Actions，推荐）

只要 `main` 分支变动，CI 自动跑完整流程：

1. 提交并推送：
   ```bash
   git add -A
   git commit -m "feat: 部署用代码"
   git push origin main
   ```
2. 进仓库 **Actions** 标签，看 **Deploy to Cloudflare Workers** 这个 workflow 是否在跑。
3. 点进去看实时日志，正常情况下会依次出现：
   - `1/4 创建 D1 数据库`（幂等，已存在则忽略）
   - `2/4 查询 D1 database_id` → 打印 `D1 database_id = xxxxxxxx-...`
   - `3/4 注入 database_id 到 wrangler.toml`
   - `4/4 处理自定义域名`（有/无 `CUSTOM_DOMAIN` 都会打印一行）
   - `Apply D1 migrations` → 应用全部迁移（含 `0007_messages.sql`）
   - `Seed admin account` → 创建管理员
   - `Deploy Worker` → 部署主站
   - `Deploy WebSocket Relay Worker (ws)` → 部署 ws 节点
4. 全绿 ✅ 即部署成功。

### 5.1 CI 到底做了什么（技术细节，可跳过）

- **D1 自动建库 + 注入 id**：CI 先 `wrangler d1 create workerbbs`（已存在也不报错），再用 `wrangler d1 list` 抓真实 `database_id`，`sed` 替换 `wrangler.toml` 里的 `REPLACE_WITH_YOUR_D1_DATABASE_ID`。所以**你不用手动填 database_id**。
- **迁移幂等**：`wrangler d1 migrations apply workerbbs --remote` 只应用「尚未应用」的迁移，重复跑安全。
- **管理员幂等**：`scripts/seed-admin.mjs` 用 `INSERT OR IGNORE`，已存在同名则跳过。
- **ws 节点独立部署**：`wrangler deploy --config ws/wrangler.toml`，并把 `WS_DOMAIN`（若有）注入 `NODE_DOMAIN`。

## 6. 部署后必须做的两件事

### 6.1 拿到两个访问地址

部署完成后，Cloudflare 会分配 `*.workers.dev` 子域。去 **Cloudflare 控制台 → Workers & Pages**：

- 主站：`workerbbs.<你的子域>.workers.dev`
- ws 节点：`workerbbs-ws.<你的子域>.workers.dev`

> 子域名由 Cloudflare 在你首次部署时自动分配（形如 `workerbbs-<随机>.workers.dev`）。可在控制台里改子域前缀。

### 6.2 登录后台，初始化站点

1. 浏览器打开主站地址 → 右上角登录（用第 4.1 节的 `ADMIN_USERNAME` / `ADMIN_PASSWORD`）。
2. 进 **设置 → 管理后台**（或直接访问 `/admin`），可配置：
   - 站点名称、强调色、背景图、简介、LOGO；
   - 邮件验证（Resend key、发件人、开关）—— **不填则注册即自动登录，无需验证邮件**；
   - 主题（上传 zip 换肤）。

### 6.3 配置 WebSocket 端点（实时推送生效的关键）

主站要**知道 ws 节点的地址**才能把事件推过去。地址存在站点设置 `ws_endpoint` 里：

1. 后台 → **实时同步** 面板。
2. 「WebSocket 端点」填：
   ```
   wss://workerbbs-ws.<你的子域>.workers.dev
   ```
   （注意协议是 `wss://`，不是 `https://`。）
3. 保存。
4. 此时点赞 / 新帖 / 回复 / 关注 / **私信** 都会经节点实时推送给在线的其他用户。

> 忘记填会怎样？后台「测试连接」会显示浏览器握手失败；普通发帖/回帖/私信**仍正常**（它们走 REST 落库），只是没有「实时 toast 通知」。填好端点后立即生效。

## 7. 自定义域名（可选）

想用自己的域名（如 `bbs.example.com`）访问主站：

1. 域名已在 **同一个 Cloudflare 账户**下托管，且 zone 状态 **Active**。
2. 在第 4.1 节把 `CUSTOM_DOMAIN` 设成 `bbs.example.com`。
3. 确保 Token 有该域名的 **DNS:Edit** 权限（见 2.2）。
4. 推送 `main` → CI 会把地址注入 `wrangler.toml` 的 `routes`，部署时 Cloudflare **自动加好 DNS 记录**（你不用去 DNS 面板手动加）。
5. 部署完直接访问 `https://bbs.example.com`。

> 自定义域名**只影响主站**，不影响 ws 节点（ws 节点仍走 `*.workers.dev`，后台填 `wss://workerbbs-ws.<子域>.workers.dev` 即可）。

## 8. 本地手动部署（不用 GitHub Actions）

适合你只想在自己机器上推一次、或调试部署问题。

```bash
# 0) 安装依赖
npm install

# 1) 登录 Cloudflare（或 export CLOUDFLARE_API_TOKEN / CLOUDFLARE_ACCOUNT_ID）
npx wrangler login

# 2) 建 D1 库，把返回的 database_id 填进 wrangler.toml 的 database_id 字段
npx wrangler d1 create workerbbs

# 3) 应用迁移（建表 + 预置板块/设置，含私信表 0007）
npx wrangler d1 migrations apply workerbbs --remote

# 4) 创建管理员（与 Worker 端哈希参数一致：PBKDF2-SHA256 10万次）
ADMIN_EMAIL=admin@example.com ADMIN_USERNAME=admin ADMIN_PASSWORD=你的密码 node scripts/seed-admin.mjs

# 5) 部署主站
npx wrangler deploy

# 6) 部署 ws 节点（可选先改 ws/wrangler.toml 的 NODE_DOMAIN，不改也能跑）
cd ws
npx wrangler deploy --config ws/wrangler.toml
cd ..

# 7) 打开主站地址，登录后台，按 6.3 填 wss 端点
```

> 本地 `wrangler dev` 可用于开发联调（默认 `http://localhost:8787`），但它连的是**本地 D1**，与线上数据隔离，不会污染线上。

## 9. 后续更新 / 重新部署

- **代码改动想上线**：`git add -A && git commit && git push origin main` → CI 自动重跑部署，无需任何额外操作。
- **新增 D1 迁移**（如以后再加表）：在 `migrations/` 新建 `0008_xxx.sql`，推送后 CI 的 `d1 migrations apply` 会自动应用。**不要手动改已上线的迁移文件**。
- **只改前端 `public/`**：前端随主站 Worker 一起部署，推送即生效，无单独构建。

## 10. D1 数据库与迁移速查

已存在的迁移（按应用顺序）：

| 文件 | 内容 |
|------|------|
| `0001_init.sql` | 用户、会话、板块、帖子、回复、设置等核心表 |
| `0002_sessions.sql` | 会话表补强 |
| `0003_seed.sql` | 预置板块、默认设置 |
| `0004_social.sql` | 关注 / 点赞表 |
| `0005_email.sql` | 邮箱验证字段 |
| `0006_plugins.sql` | 插件表 + 插件 KV 表 |
| `0007_messages.sql` | **私信表 `messages`**（本版新增）+ 索引 |

常用命令：

```bash
# 查看已应用 / 待应用迁移
npx wrangler d1 migrations list workerbbs --remote

# 应用（CI 已自动做；手动补跑也安全，幂等）
npx wrangler d1 migrations apply workerbbs --remote

# 进 D1 控制台执行 SQL（排查数据用）
npx wrangler d1 execute workerbbs --remote --command "SELECT count(*) FROM messages;"
```

## 12. 故障排查

| 现象 / 报错 | 原因 | 解决 |
|------------|------|------|
| CI 报 `code: 10097` / `must create a namespace using a new_sqlite_classes migration` | ws 节点 DO 迁移写法不对 | 确认 `ws/wrangler.toml` 用的是 `new_sqlite_classes = ["Relay"]`（免费套餐必须用这个，已写好）。 |
| CI 报 `7404` / `d1 info` 找不到库 | 旧脚本误用 `d1 info` 拿占位符 id 查 API | CI 已改用 `d1 list` 抓真实 id，请确保部署的是最新 `deploy.yml`（含 `REPLACE_WITH_YOUR_D1_DATABASE_ID` 的 sed 注入）。 |
| CI 报 `authentication failed` / `unauthorized` / `permission denied` | `CLOUDFLARE_API_TOKEN` 无效或权限不足 | 重新生成 Token，确认含 **D1:Edit** + **Workers Scripts:Edit**；确认 `CLOUDFLARE_ACCOUNT_ID` 正确。 |
| 自定义域名部署失败 | 域名不在同一账户 / zone 非 Active / Token 无 DNS:Edit | 把域名托管到该 Cloudflare 账户并设为 Active；Token 加 **DNS:Edit**；或先留空 `CUSTOM_DOMAIN` 用 `*.workers.dev`。 |
| 后台「测试连接」：浏览器握手失败 / 实时通知收不到 | 没填 `ws_endpoint` 或填错 | 按 6.3 把 `wss://workerbbs-ws.<子域>.workers.dev` 填进后台「实时同步」。 |
| 私信收不到实时推送，但 REST 能发 | 同上，或 ws 节点没部署 | 确认 `workerbbs-ws` 已部署；后台端点正确。 |
| 私信历史读不到 / 报 404 | 迁移没跑 / `0007_messages.sql` 未应用 | `npx wrangler d1 migrations apply workerbbs --remote`。 |
| 登录后跳回登录页 | 管理员没建成功（secrets 漏了 `ADMIN_EMAIL`/`ADMIN_PASSWORD`） | 补 Secrets 后重新推送，或本地跑 `seed-admin.mjs`。 |

## 13. 安全与运维提醒

- **ws 节点当前开放广播（无鉴权）**：任何人连上节点都能推事件。论坛内私信内容仍只投给目标用户（靠节点 `auth(userId)` + `to` 定向），但广播通道本身无密钥保护。若要上生产且担心滥用，可给 ws 节点加 `API_KEY`（`ws/src/index.ts` 与 `src/realtime.ts` 已留好开关）。
- **管理员密码只在首次创建时写入**，之后改密码请登录后台「我的资料 / 设置」改，或在 D1 里直接更新 `pass_hash`。
- **密钥永不进代码**：所有凭证走 GitHub Secrets，本地也只走环境变量。
- **数据备份**：D1 可在 Cloudflare 控制台导出；重要运营数据建议定期导出。
- **回滚**：GitHub 上把 `main` 回退到上一个正常 commit 再推送，CI 会重新部署旧版本（注意迁移一般不可自动回退，回滚代码前确认表结构兼容）。
