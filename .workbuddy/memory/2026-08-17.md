## 图标大小不一（已修）
- 用户反馈左侧栏图标"大小不一/诡异"。根因：Fluent 线性(Regular)图标的字形在 24 网格里占格不同（汉堡 20×14.5、person 16×20、其余 17–19），塞进同一 20px 框就显得大小不一 —— 不是渲染像素问题，是光学尺寸不一致。

## 修复 CI 部署失败（exit 1 @ Provision 步骤）
- 现象：GitHub Actions 第 3 次运行在 "Provision D1 & R2" 步骤 `exit 1`，但原脚本用 `2>/dev/null` 吞掉了真实报错，看不到原因。
- 根因：原逻辑 `DB_JSON=$(d1 info --json || d1 create --json)`。`d1 create` 在**库已存在**时报错且不输出 id（重复运行场景，库早建好了）；若 `d1 info` 也异常则两边皆空 → `DB_ID` 为空 → `exit 1`。
- 修复：改为**幂等**——`d1 create ... || true`（已存在忽略）→ `d1 info` 取 id；并把 Cloudflare 原始报错 `cat` 出来便于排查（多为 token 缺 `D1:Edit` 权限）。自定义域名 sed 分隔符由 `/` 改 `|` 防特殊字符。提交并推送 `0b4ba14`。
- 经验：CI 脚本里的 `2>/dev/null` 会掩盖失败原因，排查类步骤应保留错误输出。

## 再修 CI Provision 步骤 exit 1（commit 733c8cf，本地已提交未推送）
- 现象：`0b4ba14` 修完后**仍**在 Provision 步骤 exit 1，且只看到光秃秃的"错误：流程完成，出口代码1"，拿不到 Cloudflare 报错。
- **真正根因**：`set -e` 下第 41 行 `DB_OUT=$(npx wrangler d1 info workerbbs --json 2>/tmp/d1_info_err)` 没有任何 `|| true` 兜底。只要 `d1 info` 返回非 0（库未建出 / token 无权限 / account id 错），`set -e` 会**直接在该行中止**，根本走不到下面那段"打印原始报错、exit 1"的 `if [ -z "$DB_ID" ]` 分支——所以错误分支成了死代码，用户永远看不到原因。用户贴的失败日志是脚本被翻译的版本（集合 -e=set -e，确实如此=|| true，壳牌=shell:）。
- 修复：① 给 `d1 info`(及所有会失败的行)加 `|| true`；② 去掉对 `--json` 的强依赖，直接用正则吞 UUID（table/json 都能匹配）；③ 增加 create 输出兜底抓取 id；④ 真正打印 `d1 create`/`d1 info` 原始输出，并自动 grep 关键词(authentication/permission/10000/9109)提示"是不是 token 权限问题"；⑤ 自定义域名提示需 DNS:Edit。
- **最可能根因（需用户确认）**：`CLOUDFLARE_API_TOKEN` 缺 `Account · D1:Edit`（可能也缺 R2:Edit、DNS:Edit）。按用户约定"部署我自己来"，本次只本地提交，push 交用户触发。YAML 已校验无 tab、`run: |` 完好。
